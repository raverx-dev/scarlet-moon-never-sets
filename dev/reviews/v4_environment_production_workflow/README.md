# Scarlet Moon V4 Environment Production Workflow v1

**Issues:** #50, #51
**Parent:** #24
**Status:** Owner-accepted workflow, empirically validated by #51
**Construction authority:** #44 Late-Cartridge Profile
**Workmanship evidence:** #40 V4 Environmental Style Guide

This directory records the repeatable V4 environment-production method recovered,
reconciled, and tested under #50/#51.

It does not replace #40 or #44. It tells future environment work how to use the
existing authorities, historical evidence, RoboPixel canonical authoring, scene
composition, Owner review, correction, and Production Handoff v1 as one repeatable
production loop.

The central result is:

> V4 environments are built from canonical reusable assets and deterministic native
> composition. V3 construction economy is retained as evidence, while #40 governs
> workmanship and #44 governs Late-Cartridge construction. Mechanical correctness
> and artistic acceptance are separate gates.

## What this workflow proved

The #51 Mansion proof showed that a scene can have:

- a reusable canonical RoboPixel resident bank;
- explicit 8x8 tile and 16x16 metatile evidence;
- four shared background subpalettes and a stage-local bank;
- larger structures and a unique landmark without flattening the scene into one image;
- deterministic integer composition outside RoboPixel;
- native 1x Owner review;
- targeted correction that preserves good assets;
- exact Production Handoff v1 reconstruction and verification.

The first #51 composition was mechanically correct but artistically rejected.
Correction preserved 40 selected bank assets unchanged, revised only the rose
landmark, and substantially improved the result through recomposition. This is a
core workflow result: asset-bank acceptance and scene-composition acceptance are
different decisions.

## Scope boundary

This workflow governs static environment/tile/scene production.

It does not:

- infer the character raster-recovery/BOX workflow for environments;
- require every visible form to be a tiny repeated 8x8 tile;
- permit unrestricted flattened background illustration;
- make mechanical validation an aesthetic score;
- authorize runtime integration before art acceptance;
- promote RoboPixel's conceptual Machine Profile Stack into implementation authority;
- prove untested SNES, Mega Drive/Genesis, Game Boy, arcade, or other profiles.

Those broader profiles remain future empirical work.

## Deferred operational concern

Long, tool-heavy environment Work sessions have repeatedly stalled or timed out after
substantial RoboPixel authoring. That reliability problem is intentionally separate
from this workflow/art-method closeout and should be investigated as a follow-up
without reopening the accepted production method.
